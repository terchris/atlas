# website/

User-facing documentation for the Atlas data platform. **Docusaurus-shaped, but Docusaurus is not yet installed.** The folder layout matches the conventions used in sister Helpers projects ([urbalurba-infrastructure](https://github.com/helpers-no/urbalurba-infrastructure) and [devcontainer-toolbox](https://github.com/helpers-no/devcontainer-toolbox)) so that installing Docusaurus later requires no restructuring.

## What this folder is

The home for documentation aimed at people *using* the `marts.*` schema and the Atlas product as a whole:

- **Dev** (tertiary persona) — developer exploring public data about Norwegian civil society
- **Ola** (primary persona) — data-curious observer (journalist, researcher, citizen)
- **Lisa** (secondary persona) — tilskuddsansvarlig at an NGO, consumer of need indicators
- **Signe** (secondary persona) — national-office planner
- **LLM agents** — future external consumers querying the platform via API or natural language

It's deliberately **separate from**:

- [`docs/research/`](../docs/research/) — research notes (audience: the team thinking about the model)
- [`docs/ai-developer/`](../docs/ai-developer/) — implementation plans (audience: the team building the codebase) — *planned to move into `website/docs/ai-developer/` in a future PR, matching UIS convention*
- [`atlas-data/`](../atlas-data/) — operational docs for people running the data pipeline

## Why Docusaurus-shaped

[Docusaurus](https://docusaurus.io) is the planned eventual renderer. By matching the conventions used in sibling Helpers projects now, we can install Docusaurus later without restructuring content.

### Conventions inherited from sister Helpers sites

Studied from [urbalurba-infrastructure/website/](https://github.com/helpers-no/urbalurba-infrastructure/tree/main/website) and [devcontainer-toolbox/website/](https://github.com/helpers-no/devcontainer-toolbox/tree/main/website):

| Convention | What it means here |
|---|---|
| **Docusaurus 3.9.2** | The version pinned across both sister projects. Use the same when installing. |
| **TypeScript config** | `docusaurus.config.ts` and `sidebars.ts`, not the JS variants. |
| **`docs/index.md` as the landing page** | Not `intro.md`. Docusaurus auto-routes it to `/docs/`. |
| **Minimal frontmatter** | Often no frontmatter at all — pages rely on the `# Heading` and folder position. When frontmatter is needed, just `title:` + `sidebar_position:`. Avoid over-specifying `id`, `description`, `slug` unless required. |
| **Hand-curated `sidebars.ts`** | Both sister sites curate the main sidebar by hand. `_category_.json` is fallback for `autogenerated` sidebars. |
| **`_category_.json` shape** | `{ label, position, link: { type: "generated-index" \| "doc", description?, id? } }`. Use `type: "doc"` when the category has an overview MD page; `type: "generated-index"` when not. |
| **Search plugin** | `@easyops-cn/docusaurus-search-local` (used by both). |
| **Diagrams** | `@docusaurus/theme-mermaid` (used by both). Mermaid in markdown enabled. |
| **`onBrokenLinks: 'warn'`** | UIS uses `'warn'` (friendlier during early dev). DCT uses `'throw'`. We'll go with `'warn'` to match UIS. |
| **`README.md` works as a doc** | UIS references `id: ai-developer/README` in sidebars without renaming. Files can keep their existing names. |

### What's already Docusaurus-compatible in this folder today

- `docs/` is the docs root (Docusaurus default)
- Each subfolder is a sidebar category (controlled by `_category_.json`)
- `index.md` is the canonical landing page (matches sister-site convention)
- Markdown files use minimal frontmatter where needed

When Docusaurus is installed, expected additions:

- `package.json` + `docusaurus.config.ts` + `sidebars.ts` at this level
- `src/` for any custom React components and CSS
- `static/` for images and downloads
- `build/` (gitignored) for the generated site

## Adding a page

1. Create the `.md` file in the right subfolder.
2. Add minimal Docusaurus frontmatter at the top *only if needed*:

   ```markdown
   ---
   title: <Page Title>
   sidebar_position: <integer>
   ---
   ```

   Skip the frontmatter entirely if the page's `# Heading` and folder position are sufficient — that's the common pattern in the sister sites.

3. Use markdown links to other pages with **relative paths** (e.g. `[reading a row](./getting-started/reading-a-row.md)`) — Docusaurus rewrites these correctly when it renders.
4. Use markdown links to repo files outside `website/` with **paths from this folder** (e.g. `[fact_kommune_indicators.sql](../atlas-data/dbt/models/marts/fact_kommune_indicators.sql)`) — works in GitHub today; will need adjustment when Docusaurus is installed.

## When does Docusaurus get installed?

Triggered by any of:
- 3+ pages in `concepts/` and 3+ in `measurements/` (enough content that browsing matters)
- First external consumer asks for "where's the API documentation?"
- Tilskuddsmatcher v1 ships and Lisa-style users need a reference

Until one of those: keep content here in MD form, navigated via GitHub.

When the time comes, the install command — borrowed from the sister projects — is approximately:

```bash
cd website
npm init -y                                # if package.json doesn't yet exist
npm install --save \
  @docusaurus/core@3.9.2 \
  @docusaurus/preset-classic@3.9.2 \
  @docusaurus/theme-mermaid@3.9.2 \
  @easyops-cn/docusaurus-search-local \
  docusaurus-plugin-image-zoom \
  prism-react-renderer react react-dom
```

Then create `docusaurus.config.ts` and `sidebars.ts` modelled on the [UIS versions](https://github.com/helpers-no/urbalurba-infrastructure/tree/main/website).
